# Responsibilities

`Client` is an `httpx.Client` subclass that the supervisor uses for every Execution API call. It attaches the bearer token (`BearerAuth`), adds correlation and trace headers, retries transient failures, and maps 4xx/5xx responses to `ServerResponseError`. Operations are grouped by resource on the client (`client.task_instances`, `client.xcoms`, and so on), each a class such as `TaskInstanceOperations` or `XComOperations`. `_generated.py` is produced from the server's OpenAPI document for the newest Execution API version and is the only source of request and response types the client uses.

| `API_VERSION` (in `_generated.py`) | The Execution API version the generated models target. |

# Gotchas

- Heartbeats are not retried by the client. Commit `cb9765fa4e` ("Don't retry task heartbeats according to `[workers] execution_api_retries`") moved heartbeat retry policy to the supervisor, because client backoff blocked log forwarding during an API outage.
- A 409 that means "already running" is converted to `TaskAlreadyRunningError` rather than a generic failure. Commit `f5ff9671ec` added this so a redelivered task is not marked failed.
- Connection IDs and key paths may contain slashes; the client must escape them. Commits `0142b0443a` and `91cce6484c` fixed this for connections and for the DagOperations lookup.
- Commit `2b8c80568b` ("Refuse secrets-backend fallback on Execution-API authz deny") changed `client.py`, `context.py` and the secrets backend together. An authz denial must surface as an error, not as `None`, or a secrets backend chain falls through to an unchecked backend.
- Commit `7369e4645c` cached the SSL context on the client after a memory leak; a new client-construction path must reuse that cache.
- `_generated.py` is regenerated, not edited. Its header records the source filename and the generator version.
